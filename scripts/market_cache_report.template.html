问题变了，图片相同。能否沿用上一次的计算？下面把两种缓存、真实模型输出和计算掩码放在一起看。
先建立直觉

照片、视觉特征与 KV，
是三个不同的东西。

照片是像素。视觉编码器把它变成一串向量；这些向量进入语言模型后，每一层又产生自己的 K 和 V。

像素 → 视觉向量 → 逐层 K/V → 根据新问题生成回答
保留越靠后的计算结果，可能省得越多，也越需要检查上下文是否仍然适配。

向量不等于“番茄”“摊主”等人类标签。缓存也不等于保存一段旧答案：新问题和新答案仍然需要计算。

01

缓存的究竟是哪一步？

VISION FEATURES / 视觉特征

省掉重复的“看图编码”

把这张图划分为小块，经视觉 Transformer 和合并模块，得到可以送入语言模型的视觉向量。下次输入相同图片和相同预处理结果时，可以直接取回这些向量。

E = VisionEncoder(preprocess(image))

好比第一次先把整张市场照片“读成一份数值笔记”。下一次问蔬菜还是人物，都可以沿用这份视觉笔记。

本次实际命中 SGLang 的外层 embedding_cache。它在本实验进程中保留 GPU 上的视觉嵌入；仓库内还有按图片保存的 CPU 特征缓存。

KEY / VALUE CACHE / 注意力键值缓存

省掉语言模型内部的重复计算

视觉 token 和文字 token 进入语言模型后，每个注意力层产生 K、V。新 token 的 Q 会与已有 K 匹配，再从 V 读取信息。KV Cache 保留的就是这些逐层中间张量。

Kₗ = Xₗ Wᴷₗ　 Vₗ = Xₗ Wⱽₗ
Attention(Q,K,V) = softmax(QKᵀ / √d + mask)V

不只是保留视觉笔记，还保留“每一层已经怎样处理过这份笔记”的记录。注意：更深层记录会受到前文影响，换问题时未必能完全照搬。

Q 是当前 token 的查询向量，不是整句自然语言问题。这里复用的是图像 token 对应的 K/V。

主视觉嵌入与 3 组 DeepStack 特征拼接，宽度为 4 × 4096。一次冷请求同时保存外层 GPU 嵌入和内层 CPU 副本。

图像对应的逐层 K/V
MiB

36 层 × 每层 K、V 各一份 = 72 个张量。

每个张量的宽度为 8 个 KV 头 × 128 维。仓库 MockKVManager 将这些图像 K/V 保存在 CPU 内存，复用时复制回 GPU。

单张图的 CPU 缓存数据
MiB

CPU 视觉特征副本 + CPU 图像 K/V。

外层 GPU 嵌入缓存还占一份视觉特征数据。以上只统计张量本体，不是整个服务的显存或主存峰值。

06

什么时候可以复用，什么时候要重算？

输入发生的变化视觉特征语言模型的图像 K/V
同图、同预处理、换一个文字问题通常可以直接复用前文变化会影响深层状态；本仓库采用部分重算
同图、同题、完全相同前缀可以复用更容易保持一致；仍须验证实现与数值差异
裁剪、改分辨率、改像素或图像顺序需按实际预处理结果重新匹配不能默认沿用；位置与上下文可能变化
换成另一张市场照片新内容要重新计算不能因“都是市场”就复用旧张量
更换模型权重、视觉配置或 dtype旧特征不再默认兼容应失效或严格版本隔离
分清两件事：普通自回归 KV Cache 复用的是同一前缀中已经确定的历史状态。SceneCache 进一步尝试把图像中间结果跨请求带走，并通过重算一部分图像 token 来适应新上下文。后者在本仓库中属于近似计算。
07

实现细节与证据

本张图片的输入到底经过了什么处理？

先以 16 × 16 像素为 patch，再按 2 × 2 个 patch 合并为一个视觉 token。图上的格网是这个合并后的 token 位置示意；位置投影不代表每个特征只含对应小块的信息，因为视觉注意力会融合上下文。

为什么缓存图像 KV 还要重算一部分？

语言模型深层的图像表示包含对前文的注意力结果。新问题在图片之前时，改变的不只是文字，后续图像状态也可能改变。这个分支默认每层重算约 30% 的图像 token，沿用剩余部分；取整后，本例不是恰好 30% / 70%。

本仓库在 Qwen3Attention 中保存尚未做 K 归一化和 RoPE 的 K，以及 V。取回后重新应用归一化和位置编码，帮助适配位置变化；这并不能消除更深层状态对旧上下文的依赖。

为什么 SGLang 日志的 cached-token=0，仍然有缓存复用？

这次关闭了普通 Radix 前缀缓存，避免它混入实验。日志中的 cached-token 主要描述该前缀缓存；本分支另有图像 embedding_cache、MockKVManager 和 compute_mask。报告直接追踪这些方法与掩码，所以可以观察到“前缀缓存为 0，图像缓存仍然命中”。
